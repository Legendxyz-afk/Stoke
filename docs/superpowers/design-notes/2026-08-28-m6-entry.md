# M6 entry — the rung order, and why the server is built ON the ABI

M6 is `stoke.h` freeze + server. **This note is a work plan, not a design.** The
design was LOCKED on 2026-07-19 in
`2026-07-19-m3-m7-forward-designs-and-risk-playbook.md` §M6 — the error-handling
split, the ABI freeze checklist, the server design and the OpenAI compat trap
list are all decided there, explicitly so that "no design authority is needed
later". Nothing below reopens any of it. What this note adds is the ORDER, the
two claims that order rests on, and the corrections the code forced.

---

## 1. What already exists, and it is more than it looks

**`sched.h` is already ABI-shaped.** It hands out an opaque `Sched*`, and its
surface is `sched_submit` / `sched_poll` / `sched_cancel` / `sched_step`, with
`sched_poll(s, id, out, cap, finish)` already caller-owns-buffer-with-explicit-cap
— the exact `tok.h` pattern the freeze checklist mandates. `stoke.h` is
therefore mostly a stable RE-EXPRESSION of a shape that exists and is tested,
not a new abstraction over it. That is the single biggest reason M6 is smaller
than it reads.

**`serve.h` is NOT the server.** `ServeHost` is the in-process driver behind
`bench --serve`, and `server.c` (HTTP) is a new file that does not replace it.
Both stay: the in-process host is what every M5 gate measures, and it must keep
working unchanged or the M5 numbers stop being reproducible.

**The M0 adapter contract is three methods.** `bench/adapters.py` subclasses
`Adapter` with `_spawn()`, `_healthy()` and a `base_url`/`host`/`port`; the
harness does the rest over OpenAI-SSE. Gate item [3] is therefore not a large
piece of work — it is a small piece of work that FAILS LOUDLY if the compat
surface is wrong, which is exactly why it is the gate's core.

## 2. Two corrections the code forced on the forward note

1. **"~90 `fatal()` call sites" is wrong — there are 322.** Verified by count,
   not estimated. The design is untouched (no call site changes; the choke point
   in `common.h` gains the trap check) — but the number matters because it is
   what makes "no call site changes" load-bearing rather than a convenience.
   Any plan that assumed a 90-site sweep as a fallback should drop it: at 322
   sites a manual sweep is not a fallback, it is a different project.

2. **`fatal()` is `static inline` in a header, so the trap state cannot be.**
   Every translation unit compiles its own copy of `fatal`. The thread-local
   `jmp_buf` and the error buffer must therefore be ONE shared object with
   external linkage (declared in `common.h`, defined in exactly one `.c`), not
   a `static` beside the inline function — that would give each TU its own trap
   state, and whether a `longjmp` worked would depend on WHICH TU raised the
   error. That is a silent, load-bearing, arch-dependent bug and it is the
   first thing to get right. `_Noreturn` stays valid and stays on: a trapping
   `fatal()` still never returns to its caller.

## 3. THE ORDERING DECISION: the server is a CONSUMER of `stoke.h`, not a sibling

`server.c` could reach into `sched.h` and `model.h` directly — it lives in the
same tree and nothing stops it. **It must not.**

The freeze at the end of M6 is a promise that the ABI is right. The only thing
in this milestone that will exercise the ABI hard enough to find out — streaming
under cancellation, concurrent submits, poll-with-cap against a slow socket,
errors on malformed input — is the server. If the server bypasses the header,
the ABI ships having been used by nothing, and the freeze is a guess dressed as
a checklist. **Building the server on `stoke.h` converts the ABI checklist from
a review into a report on something that already happened.**

Concretely: `server.c` includes `stoke.h` and nothing else from `src/`. If it
ever needs something the header does not expose, that is a finding about the
header, to be fixed in the header — not routed around.

## 4. The entry rungs

Ordered so that the thing most likely to fail late — OpenAI compatibility —
fails as early as it can be made to.

### A1 — `stoke.h` v0 and the error-handling split
The opaque handle, open/close/submit/poll/cancel, `stoke_last_error()`,
`stoke_abi_version()`, the `STOKE_ERR_*` enum, and the three-class failure split
from the forward note. **The C++ TU compile test joins the matrix in this rung,
not at the gate** — it costs one file and it catches header mistakes while the
header is still free to change. NOT frozen; v0 is explicitly provisional.

### A2 — the socket shim and the HTTP/1.1 parser
Winsock/POSIX behind the ~50-line shim; bounded request line and headers with
loud 431/413; Content-Length bodies only. **Buildable and testable with no model
loaded**, which makes it the cheapest rung to harden — and its committed
garbage-input corpus IS gate item [6], so that item is banked here rather than
scrambled for at the end.

### A3 — the vertical slice: `/health` + non-streaming `/v1/chat/completions`
Real inference, greedy, no sampling extras. The earliest point at which
something real answers a real client. Curl goldens committed here = gate [2].

### A4 — SSE, and the trap list checked one at a time
`data:` framing, `: ping` heartbeat every 15 s, `[DONE]`; first delta carries
`role`; `finish_reason` null-until-final; `usage` only under
`stream_options.include_usage`; per-connection bounded buffer, overflow
disconnects and cancels that request. **Never block the scheduler on a socket.**

### A5 — point the M0 harness at it  ← THE GATE'S CORE, DELIBERATELY EARLY
Write `StokeAdapter`, run the harness UNMODIFIED. Placed before the sampling
work because a compat failure found here is cheap and the same failure found
after A6 is expensive. ⚠ **Open, to resolve on arrival rather than guess now:
whether the harness's scenarios need any sampling parameter A3–A4 has not
built.** If they do, the minimum needed moves forward from A6 into A5 — the
harness's requirements decide, not this note.

### A6 — the sampling set and stop strings
temperature / top-k / top-p / repeat-penalty / stop / seed; per-request
splitmix64 sampled on the scheduler thread. Stop strings cross token boundaries,
so the server holds a per-request tail window of `max stop-string bytes − 1`,
checks after each token, cancels on hit and drops the overshoot.

### A7 — the freeze
The ABI checklist as a mechanical all-boxes pass, the matrix + a 10-minute
randomized ASan serve smoke, then the header is TAGGED FROZEN.

## 6. Standing constraints this milestone inherits

M6 is the first milestone whose gates are mostly FUNCTIONAL rather than
measured, which removes most of the measurement hazard — but not all of it, and
the ones that survive are the ones that bite:

- **Any perf claim still needs a same-sitting one-binary A/B.** The 2026-08-28
  finding stands: this box's fixed llama referent moved `pp512` +27.8% between
  sittings while `tg128` moved +7.4%. No cross-sitting attributions.
- **The in-process M5 numbers must not move.** `serve.c` stays as it is; if a
  refactor for `stoke.h` touches the scheduler, the M5 bars are re-measured or
  the refactor does not land.
- **Every bank or cache keyed by the binary.** Three sightings in M5.
- **Gate sittings foreground, sliced one unit per invocation.**
- **Build and test from bash**, not PowerShell: `mingw32-make`, then
  `sh tests/run_tests.sh build/win .exe` plus the four goldens.

## 7. Deliberately deferred, with the reason attached

- **Inbound chunked transfer-encoding.** Clients do not send it; v1 is
  Content-Length only, and the parser returns a loud error rather than
  mis-parsing. Revisit only if a real client is observed needing it.
- **Runtime malloc OOM during serving** lands in the abort class for v1, per the
  forward note, and is documented rather than handled. KV exhaustion is NOT an
  error at all — the scheduler preempts; that is the M5 design.
- **Merging `m5-entry` into `main`.** Every prior milestone left `main` on the
  closed tag and `main` is currently ~220 commits behind at `m45`. Kabir's call,
  raised 2026-08-28 and not yet answered; M6 proceeds on `m5-entry` either way.
