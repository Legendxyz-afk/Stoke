# M4 — Q8 KV: the representation, and the accessor it cannot fit through

## 1. The bar, quoted rather than paraphrased

Ruling §8.1: the criterion is **KV-ON vs KV-OFF, within-stoke, same engine, only
the KV representation differing** — graded by §6 with its own τ frozen from an
M4 entry probe of the ON↔OFF pair, **zero BUG-class**, and class divergences
bounded by **first-divergence prompt rate ≤ 19/50 AND flip rate ≤ 0.5%/token**,
both on the frozen 50-corpus. Exceeding it is a results-vs-physics memo about
the quantizer, not a grind.

Playbook N4 adds the property bound: **|dq(q(x)) − x| ≤ d/2 per element**.

Two things follow that are easy to lose. The criterion is *within-stoke*: there
is no oracle here, and the two sides differ in exactly one thing. And Q8-KV is
never token-parity-gated — divergence is expected and *counted*, which is why
the bound is a rate and not zero.

## 2. What the artifact actually says

`kv_view(kv, layer, kv_head, pos)` returns `KvSlot { f32* k; f32* v; }` —
**writable pointers into storage**. `src/model.c` uses it for both directions:

```c
/* write, once per (layer, kv_head) at the current position */
KvSlot slot = kv_view(kvs, L, h, pos);
memcpy(slot.k, sc->s_k + h*head_dim, head_dim*sizeof(f32));

/* read, for every j <= pos, twice per position (scores, then weighted V) */
KvSlot slot = kv_view(kvs, L, kvh, j);
sc->s_scores[j] = vec_dot_f32(qh, slot.k, head_dim) * scale;
```

**A quantized store cannot serve that signature.** There is no f32 address to
hand back: the bytes are int8 plus a scale, and a caller that writes through the
returned pointer is writing into whatever the dequantizer happened to use.

This is not a limitation of the quantizer. It is the accessor's *shape* — a
pointer is a promise about representation, and M2 made that promise when only
one representation existed. The body swap (`63153f6`) kept the promise because
paging changes *where* an f32 vector lives, not *what it is*.

## 3. Options, and the decision

**(a) An explicit read/write pair — CHOSEN.**

```c
void   kv_store(Kv*, u32 layer, u32 kv_head, u32 pos, const f32* k, const f32* v);
KvSlot kv_load (Kv*, u32 layer, u32 kv_head, u32 pos, f32* scratch);
```

`kv_load`'s returned pointers are either *directly into storage* (f32 mode —
zero copy, so f32 stays exactly as fast and exactly as exact as it is today) or
*into the caller's scratch* (Q8 mode). `kv_view` remains, unchanged, as the
f32-mode accessor the tests use.

**(b) Dequantize-on-read into an internal rotating scratch, keeping `kv_view`.**
Reads would work — model.c consumes each slot before requesting the next. Writes
would be silently lost, since `memcpy(slot.k, …)` would land in the scratch.
Rejected: the failure is invisible and produces plausible output, which is the
same class this milestone has already refused twice (the "current sequence"
setter in the body-swap note, and a dedup that trusts its hash).

**(c) f32 tail block, quantized full blocks.** Writes only ever touch the tail
(KV is append-only, §3.4 of the block-pool note), so `kv_view` could keep
returning a real pointer for writes while full blocks dequantize into scratch.
Genuinely clever, and it preserves the frozen signature. Rejected because it
leaves a pointer that is writable in the type system and read-only in fact: a
caller writing to a full block's slot loses the write with no diagnostic. A
contract that cannot be checked is one that will eventually be broken.

**Why (a) is worth the churn.** It puts the read/write distinction in the type
system, where the compiler enforces it, instead of in a comment. It costs one
mechanical edit to model.c's attention loop and one extra scratch buffer per
sequence. And it is representation-independent by construction, which is what
M5's Q8 default and any later device path both need.

**What survives of M2's rule.** "kv_view is the ONLY way anything computes a KV
address" was about *one place owning address arithmetic*. That still holds:
`kv_load`/`kv_store` live in `kv.c` beside `kv_view` and share its translation.
What changes is the *signature* the engine calls through, not the ownership.

## 4. The representation

Reuse `quantize_row_q8_0` / `dequant_row_q8_0` (`src/kernels/q8_0.c`) — already
transcribed from the probed ggml reference, already tested, and already the
format the weights use. One quantizer in the codebase, not two. It is also what
llama.cpp's own q8_0 KV cache uses, so the numbers are comparable to a referent.

Block = 32 elements in 34 bytes (an f16 scale plus 32 int8). `head_dim` is 128,
so one K or V vector is 4 blocks = **136 bytes against 512 as f32**.

| | per vector | per token (36L × 8 kvh × K+V) | 16-token pool block | pool at N=16, ctx 1024 |
|---|---:|---:|---:|---:|
| f32 | 512 B | 294,912 B | 4.50 MiB | **4.83 GB** |
| Q8_0 | 136 B | 78,336 B | 1.20 MiB | **1.28 GB** |

Ratio **0.2656**, i.e. a **3.77× reduction** — computed, not recalled.

> ⚠ **"Q8-KV halves it" is an f16-era statement and must not be repeated.** The
> block-pool note's table lists Q8 at exactly ¼ of f32 (2.42 GB at N=16/2048);
> that is right to within the scale overhead this table makes explicit — 8
> bytes of f16 scale per 128-element vector, 1.6%. The *halving* language comes
> from the 08-11 bandwidth note, which was written against an assumed f16
> baseline and was corrected to f32 in `346e0d0`. Against stoke's actual
> representation the factor is ~3.8, not 2. This matters for the N=16 bar memo,
> where it is the difference between "fits with room" and "fits".

## 5. The property bound, and where it does not hold as written

The playbook asks for **|dq(q(x)) − x| ≤ d/2**. The ggml reference computes
`d = amax/127`, quantizes with `q = round(x/d)`, and **stores d as f16**.
Dequantization uses the stored value, so the reconstruction is `x̂ = f16(d)·q`,
not `d·q`:

```
|x̂ − x| ≤ |d·q − x| + |q|·|f16(d) − d| ≤ d/2 + 127·d·2⁻¹¹ ≈ 0.562·d
```

The kernel's own comment confirms the mechanism: *"`id` is computed from the f32
`d`, BEFORE d is narrowed to f16"* — deliberate, because quantizing with the
narrowed value shifts quants by ±1 near block boundaries. So **d/2 is not
GUARANTEED**, and the guaranteed bound is the one above.

**Measured, and it corrects an earlier draft of this section.** This note first
said the strict bound "is not expected to hold". That was reasoning from the
worst case as though it were the typical one. On a 32-element vector with a
deliberate outlier the worst reconstruction error is **0.4836·d (K) and 0.4894·d
(V)** — *under* d/2, because the element that attains the rounding worst case
and the element that attains the scale-narrowing worst case are not the same
element. The guarantee and the observation are different statements and both
belong here.

The property test therefore asserts the **guaranteed** bound (0.562·d) and
PRINTS the measured worst case against both. Asserting d/2 would make the test
fail one day on an input that is not a bug; asserting only the loose bound and
not printing the tight one would hide that the scheme is in practice as good as
the playbook assumed.

## 6. What has to be re-verified, and the risk

- **f32 mode must stay byte-identical.** `kv_store` is the memcpy it replaces and
  `kv_load` returns the storage pointer, so this is expected to be exact — and
  it is checked the only way that counts, against `build/stoke-m3-gate-876ce53f.exe`
  on p00 and p41 (the standing recipe; golden gates cover tokenization only).
- **K6.** This edits the attention loop, which the paged-KV measurement showed
  has ~7.3% margin over the ≥7.8 bar. An extra call per (layer, head, position)
  in the f32 path is the risk; it is a static call into the same translation
  `kv_view` already did, so the expectation is no change, and the expectation is
  worth exactly nothing until measured on a quiesced box.
- **Q8 mode's cost is a separate question from its correctness** and is not part
  of gate item 4. Recorded so it does not get smuggled into the curve.

## 7. Direction check

Kabir: this amends an M2-frozen signature — the engine will call `kv_load`/
`kv_store` where it called `kv_view`, and `kv_view` stays as the f32 accessor.
The alternative that preserves the frozen shape (option c) does so by leaving a
pointer that is writable in the type system and read-only in fact. I have taken
the churn over the unenforceable contract. Overrule if you would rather M4 keep
the signature untouched and defer Q8-KV to M5 — the cost of deferring is that
gate item 4 moves with it, and the N=16 bar memo loses its measured input.
