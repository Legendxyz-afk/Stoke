## 3. ⭐ Found closing this rung: **on Llama-3.2 the AVX2 attention arm is dead code**

Not a defect, and it changes what one existing sentence is worth.

Both SIMD blocks in `model.c`'s `att_kvheads_run` are `for (; g + 4u <= G;
g += 4u)`. At **G=4** they carry attention; at **G=3** they run **zero times**
and the scalar remainder carries 100%.

**Proved by mutation, not by reading the bounds** — perturbing
`att_score4_avx2`'s scale by 1%:

| model | G | greedy ids vs the clean binary |
|---|---|---|
| Llama-3.2-3B | **3** | **IDENTICAL** — the mutated code never runs |
| Qwen3-4B | **4** | **20 of 48 changed** — the mutation is live |

Two consequences, and the first is a correction:

1. ⚠ **The 2026-09-05 B5 note's "`STOKE_ATT_SIMD=0` and the AVX2 arm now
   produce byte-identical output" is TRUE and is NOT twin evidence on that
   model.** At G=3 the two arms are the same code. The note's *neighbouring*
   finding — that the remainder carries 100% at G=3 — is exactly why. The first
   version of today's gate made the same mistake and went green before the
   mutation caught it. `tests/att_simd_twins.sh` therefore runs its real twin
   leg on the **Qwen** file and labels the Llama leg a change-detector in its
   own output line.
2. ⏳ **Carried headroom, performance, unmeasured:** every model whose GQA group
   is not a multiple of 4 runs stoke's attention scoring **entirely scalar**.
   Llama-3.2-3B is G=3. This is a named lever for the M7 perf work and for the
   ARM port's kernel plan; it is **not** a correctness item and nothing here
   measures its size.

## 4. Also closed today, in the same family, and each proven able to fail

⚠⚠ **`STOKE_ATT_SIMD=0` was the arm the twin measurement used, and until today
an out-of-range value was silently swallowed.** `src/model.c`'s `env_u32`
returned the **default** on a non-numeric or out-of-range value. So
`STOKE_ATT_SIMD=O` (letter O), `=2`, or `= 0` would have run the default arm,
the A/B would have compared one arm with itself, and it would have agreed
bit-for-bit — [[fixture-can-be-blind-to-the-defect]]'s *"a bit-exact A/B cannot
detect that one arm never ran"*, reached through a typo. Now a **fatal**, which
is standing rule 10's idiom (`STOKE_Q6K_KERNEL`'s refusal is the only
non-circular proof its switch is live).

⭐ It also makes `STOKE_PREFILL_CHUNK`'s own header true for the first time: it
promises *"a bad value is REFUSED rather than rounded"*, and an out-of-range
value was being swallowed one function earlier, so its fatal never saw it.

⚠⚠ **And two DELETED knobs were being silently ignored, with the trap already
armed.** `att_env_init`'s header has said since M5 that `STOKE_ATT_LANES` and
`STOKE_ATT_GQA` are *"deliberately not accepted-and-ignored: a knob that
silently does nothing is worse than one that does not exist, because a later
A/B would set it, see no difference, and record that as a finding about the
kernel."* **Nothing enforced it** — they appear in `src/` only in that comment.
And **two tooling scripts in this repo still set them**
(`tests/tooling/run_att_par_verify.ps1:113,133`,
`tests/tooling/run_m5_e2_verify.ps1:155,174`), so those scripts' "arms" were all
one arm. Now refused by name. ⏳ Those two scripts are left as they are and are
hereby known-stale: they will now fatal loudly instead of measuring nothing.

## 6. Verification — and a third dead guard, found by reading the run

Full Windows matrix, `STOKE_REQUIRE_GOLDEN=1 mingw32-make test`, at the tree
this report closes: **see the commit message for the run's own output.** The
new gate is wired into `make test` (non-TSan legs; the TSan SKIP line names it
alongside the other model gates, for the measured RSS reason recorded there).

⚠⚠ **The first green matrix carried one line of stderr that turned out to be a
dead non-vacuity guard — the third of the day, and it was found by reading a
passing run rather than a failing one.**

```
tests/abi_firsttoken.sh: line 42: [: : integer expression expected
```

`abi_firsttoken.sh`'s header says the step count is what stops the gate being
vacuous: *"A run in which the racing thread never stepped … agrees with itself
perfectly and proves nothing — so the binary prints its step count and this
reads it."* **It did not read it.** The `sed` replacement was not a
backreference but a literal **0x01 (SOH)** byte, so `steps` was one control
character, the test **errored**, the `if` went false on the error, and the gate
walked on to its OK line. Dead since `f519507`.

⇒ **B3's evidence is unaffected** — the binary really did print 20534 steps and
that was read at the time. It is the standing guard that had never once been
evaluated. Now repaired, and **run red first** on all three paths: 20534 steps →
passes with `steps=20534`; **0 steps → FAILS**; no summary line → FAILS with
*"the guard could not be EVALUATED, which is not the same as passing it"*.

⚠⚠⚠ **AND THE MECHANISM REPRODUCED ITSELF, TWICE, WHILE THE FIX WAS BEING
WRITTEN.** A tool layer between the author and the file ate one backslash, so a
written backreference arrived at the writer as an **octal escape** and became
0x01 again — the second attempt looked correct in the source view and was caught
only by `grep -c $'\001'`. That is almost certainly how the original got there.
**The fix is to build the backslash from its code point rather than type it, and
to assert no control byte survives the write.** Same family as the CRLF lesson
from 2026-09-07: a source file can be wrong in a way no normal view of it shows.
A repo-wide sweep for stray control bytes in `*.c/h/sh/py/ps1/md` + `Makefile`
comes back **clean** — this was the only one.
