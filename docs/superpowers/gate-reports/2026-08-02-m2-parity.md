## 1. What this gate is, and what it deliberately is not

M2's gate was **re-scoped by Kabir on 2026-07-28** (memo option 3,
`docs/superpowers/memos/2026-07-20-m2-oracle-near-tie-policy.md`). The
original bar was 50/50 token-exact against `llama-server`. The 07-28 survey
measured **19 of 50 prompts diverging from the oracle**, and **18 of 18
classifiable hits were a clean top-2 swap** at 0.00095–0.2039 nat gaps — the
oracle quantizes activations to Q8 for integer dot products while M2's stoke
is pure f32, so the two rank near-ties differently. That is an
arithmetic-class difference, not a stoke defect.

Accordingly:

- **This gate is C-vs-ref**, both sides pure float32: stoke's C forward pass
  against `ref_forward.py`, the numpy reference.
- **Oracle token-parity is DEFERRED TO M3**, where the integer core puts
  stoke in the oracle's own numeric class and the forward note already
  mandates re-running this exact gate. Carried to M3 with it: the mandatory
  aligner fix (byte lengths from the GGUF vocab via `gguf_reader.py`; 4/50
  prompts make the aligner fatal today) and the 07-28 census as the M2-era
  baseline.
- **Subset and pass criterion were fixed BEFORE this run**, by Fable's
  binding ruling of 2026-07-28 (`8e1e618`,
  `docs/superpowers/memos/2026-07-28-m2-substitute-gate-RULING-FABLE.md`), so
  that no bar could be written after seeing a result.

**Playbook §5 checklist box 1 ("50/50 token-exact on the recorded `--clean`
run") is therefore SUPERSEDED** by the ruling's criterion, recorded here
rather than silently skipped.

is"), `stoke run --raw -f tests/tooling/validation/debug8.txt -n 1 --dump`
vs `ref_forward.py --ids 785,6722,315,9625,374 -n 1 --dump-layers`, last

```

worst layer     : L34 at 6.104e-04
threshold       : 0.001
L2: PASS -- smooth accumulation, all layers under threshold
```

The curve rises monotonically from 1.9e-06 at L00 to 6.1e-04 at L34 and eases
to 3.1e-04 at L35 — the signature of float32 non-associativity compounding
with depth. **No layer jumped more than 10× the running trend**, so no STEP
flag: nothing here looks like a structural bug in a single op.

This **reproduces the W3-landed reference result exactly** (36/36 < 1e-3,
worst L34 6.1e-4), which is the strongest available check that the ladder
has not drifted between W3 and the gate.

Dumps: `build/l2_gate_A` (stoke), `build/l2_gate_B` (ref). Note the older
`build/l2_A` / `l2_B` from 2026-07-26 are **not** valid evidence at this pair
— `ref_forward.py` was modified 2026-07-28, after they were written. That is
why the ruling requires the re-run rather than a citation.

## 5. Run conditions — and why they do not qualify the result

The run was executed by Task Scheduler (`stoke-m2-ref-gate`, `svchost`-owned,
`ExecutionTimeLimit=PT0S`, `Priority=7`) so it survives session boundaries,
across 2026-07-30 → 2026-08-02 with deliberate pauses. Results are cached
per prompt, atomically, **on the success path only** (`ref_gate.py:399`),
with `GateError` caught in memory at `:448` — so a timeout, a kill, or a
crash can never write a result. Every banked entry is a completed comparison.

Rates varied 20.22–59.25 s/pos with box state (gaming sessions, memory
pressure), which affects **wall clock only**. The comparison is exact-id
equality; it has no tolerance that box state could move.
